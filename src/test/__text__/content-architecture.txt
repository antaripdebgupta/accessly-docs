ArchitectureAccessly UI is split into four packages so that accessibility logic, visual styling, and shared utilities can evolve — and be adopted — independently.A layered architectureEach layer only knows about the one beneath it. Your application never has to depend on anything lower than the layer it chooses to consume.Your applicationApp Router / Pages RouterImports the pieces it needs — usually just @accessly-ui/react and the Tailwind preset.@accessly-ui/reactstyled componentsPre-styled, composable components. Wraps primitives and applies the Tailwind preset's design tokens.@accessly-ui/primitivesheadless logicUnstyled hooks and components: focus traps, roving tabindex, ARIA state, keyboard handling. No visual opinion at all.@accessly-ui/utilsshared internalsLow-level helpers primitives build on — id generation, live-region announcements, portal management.@accessly-ui/tailwind-preset sits beside this stack rather than inside it — it only supplies CSS custom properties and Tailwind theme tokens that @accessly-ui/react reads at build time. See Packages for exactly what each one exports.Design principlesHeadless firstEvery interaction pattern — focus management, keyboard navigation, ARIA wiring — is built once in primitives, with no assumption about markup or class names.Server Component friendlyLayout, copy, and static structure render on the server. Client boundaries are drawn only where state or browser APIs are actually needed.Composition over configurationComponents expose small, composable parts (DialogHeader, DialogFooter, DialogClose) rather than one component with dozens of boolean props.Zero-runtime stylingStyling resolves to static Tailwind classes at build time — no CSS-in-JS runtime, no style recalculation cost in the browser.How theming flows through the system1ThemeProviderReads the stored preference (or system setting) and sets a class — light or dark — on the document root before first paint.2CSS custom propertiesThat class selects a block of tokens in tokens.css — --surface, --text, --accent, and the rest.3Tailwind preset@accessly-ui/tailwind-preset maps those same custom properties onto Tailwind's theme, so bg-surface and text-accent resolve to them.4Components@accessly-ui/react components are written entirely in terms of those Tailwind utilities — never a hard-coded hex value.Server and client boundariesComponents that hold no interactive state — Avatar, Breadcrumb, Alert, Skeleton — render as Server Components by default. Anything that manages open/closed state, focus, or keyboard interaction (Dialog, DropdownMenu, Combobox, Tabs) is marked with "use client" internally — you never need to add that directive yourself when importing from @accessly-ui/react.Mixing headless and styledIt's fine to use @accessly-ui/react for most of an app and drop down to @accessly-ui/primitives for one component that needs a completely custom look — they share the same accessibility behavior, so switching layers never costs you correctness.PreviousAccessibility PrinciplesNextPackages
